# Independent resource and conversion audit

This bounded exploratory audit reads the sealed campaign003 records and immutable code. It reruns no timed measurements, imports no experiment implementation, and changes only this directory. Full-bundle hash, same-target support/algebra proofs and independent reference accuracy checks belong to the other grading work.

All **78 unsupported-conversion rows reproduce exactly**: first failed factor scope, newly-zero finite-entry count and finite log span match all raw records. These are 14 arm cells: both arms of all six CPDs and the finite-tail control. The independent parser replays scope merging, scalar offsets, subtract-max conversion and exp/log diagnostics on all 24 prepared JSONs plus all 12 original JSONs. First failed spans range from 769.749 to 3745.763; the finite-tail span is 1000. Those finite log entries represent positive ideal-real mass, so rejection is appropriate. This establishes the adapter limitation; it does not establish intrinsic impossibility of inference.

All 108 native rows are accounted for. All 12 nonzero completions match offset restoration and log-Z reconstruction, with zero offset-reconstruction delta. Nine pre-native zero-factor guards and nine native `IncompatibleEvidence` cases agree with the replayed safe positive-product condition. Exp/log diagnostics remain binary64 diagnostics, not rigorous error bounds. Every raw native row records distribution 3.3.2, and all 21 reaching native import record module 3.3.2. The manifest's method version remains `unknown`; that metadata discrepancy should be disclosed.

All 320 valid results have sidecars with ordered load/preparation/inference/result-write/outer endpoints and consistent aggregate CPU clocks. No omitted transformation, cached prepared-model inference, conditional inference query, or result serialization was found in the audited worker paths. The outer monotonic wall includes startup/imports, original JSON load, selected transformations, target fingerprint, solver calls, output and process reap. Parent-side postprocessing of the reaped result is campaign overhead. Static preparation and source acquisition are outside row clocks as declared. Solver-call clocks nest their conversion/preprocessing/kernel clocks; those phases must not be added twice. Conversion/ingestion/kernel CPU subdivisions are unavailable, so the protocol's full CPU phase-clock requirement is only partially met.

All 324 rows have monitors; sampler errors and RSS-limit rows are both zero. No observed high-water threshold exceedance was left unadjudicated. Combined observed maxima `max(sampled, worker-before-result, worker-after-result)` are 67,649,536 bytes under low and 207,355,904 under high. **175/320 worker high-water readings exceed the sampler peak**; result serialization increases high-water in 298 rows, by up to 2,392,064 bytes. Ledger `rss_peak_bytes` and the supplied summary's completed peak use sampled RSS alone. Whole-pipeline memory summaries need the combined peak while retaining the measurement scopes.

The four timeouts are simplified 1FYN batch: trial 00019 high and 00072, 00110, 00314 low. All show watchdog timeout, SIGTERM, absent result/sidecar, empty stdout/stderr and right censoring. Triggers exceed nominal limits by 26–49 ms; finish times exceed them by 43–78 ms. No worker phase record identifies the precise internal stage reached.

The requested 10 ms sampler sleep is not a verified sampling cadence: no per-sample timestamps are stored, and 47 rows have at most three samples. RSS sampling can miss transient peaks and exited descendants, and shared pages can be counted more than once. Worker high-water covers through valid result write; sidecar creation/stdout have only sampled coverage. No instantaneous memory ceiling or durable `fsync` endpoint is established. These limitations qualify memory/phase interpretation and do not invalidate the recorded outer wall outcomes.
