# Independent verdict: campaign 003

**Verified same-target pruning gives a useful local 1FYN regime; the other five proteins remain outside these counting policies.** This is a conventional inference result on fixed-AA, single-state beta1 computational models. It establishes neither a general solver winner nor an ETH or biological-prediction advance.

## Costs and useful limits

Both measured arms start from the same original JSON. Loading, propagation, algebra, target checking, solver work, result encoding/write, startup and process reaping are inside the common outer watchdog. All 320 completed-worker result/serialization-sidecar pairs reconcile. Static preparation remains separately reported; it does not make either measured arm's preprocessing free. Raw-source acquisition is excluded from this endpoint.

For **1FYN VE**, the recorded-order largest table falls from **126,443,520 to 3,810,240 bytes**. Under the low profile, all three pruned trials pass while all three baseline trials hit the 16 MiB table policy. Under the high profile, both arms pass all three repeats:

| Cold high-profile VE | Baseline simplified | Pruned then simplified |
|---|---:|---:|
| End-to-end wall range | 0.393–0.506 s | 0.128–0.181 s |
| Whole-process observed peak range | 206–207 MB | 41.6–41.9 MB |

The three matched wall ratios are **2.17–3.91**, with the same direction under both observed arm orders; CPU ratios are **2.30–2.55**. The ranges remain separated after charging propagation. This supports a bounded local cost observation, not a portable speedup factor.

For **1FYN batch enumeration**, all six pruned trials pass. Baseline low-profile trials all time out; high-profile baseline has two completions and one timeout. The two completed high-profile baseline runs take 15.13–15.44 s versus 0.50–0.79 s for the three pruned runs. Censored rows are retained and are not infinite speedups. Pruned batch peak memory is slightly **higher**: approximately 67 MB versus 65 MB for completed baseline rows. The VE memory benefit must not be generalized across methods.

All five larger proteins still receive state/table/conversion rejections, with no partition-function completion. The established comparator supplies no completed protein comparison: all **78 conversion rejections independently reproduce positive-entry underflow**. This is an adapter representation limit, not a mathematical impossibility. Native offset restoration checks pass for all 12 finite native completions; the 18 native zero completions agree with independent zero checks. The final method-version field says `unknown`; all 108 native worker records identify installed distribution 3.3.2, and all 21 reaching import identify module 3.3.2. This metadata defect remains disclosed.

Named table policies, heuristic workspace estimates, sampled RSS and worker lifetime high-water remain distinct. Ledger/summary peak fields use sampled RSS alone; this audit's memory ranges use the maximum of sampled and both worker high-water readings. Worker high-water exceeds the sample in 175 completed rows, and serialization increases it in 298. The nominal 10 ms interval is a requested sleep, not a verified cadence. No instantaneous ceiling is guaranteed; high-water includes preparation and result writing, not just the kernel. The four timeouts finish 43–78 ms beyond their nominal wall limits and have no internal phase records.

Controller ingestion, hashing and reference validation occur after the worker row clock; total campaign elapsed time includes them. The sum of row walls is 134.74 s versus 136.42 s for campaign execution, within the frozen 900 s budget. Aggregate solver CPU is available; conversion/ingestion/kernel CPU subdivisions are not. Solver-call and internal wall phases are nested and must not be added together. These scope limits qualify comparison without changing the local completion or large memory findings.

Across 39 cells with three correct completions, wall max/min has median **1.40** and maximum **2.38**; phase ratios are much less stable, especially for tiny operations. Median repeat-2/repeat-0 wall ratio is **0.86**. Host-load telemetry does not establish a cause. These observations block a broad timing ranking or stable crossover claim. They do not erase the large, repeat-consistent local 1FYN feasibility/table/RSS observation. No early trial, timeout or unfavorable memory result is removed.
